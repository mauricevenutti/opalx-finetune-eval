2LLM judge

An LLM judge (the simple-judge skill) scores every fine-tuned answer from 1 to 10 against the reference answer and the source chunk of the manual. It never sees the base model's answer and uses no knowledge outside the reference and chunk, so invented details count as wrong. With each score it states how certain it is:

high
the reference and chunk settle every claim of the answer; another careful judge would give the same score ±1.
medium
part of the answer is not covered by the reference or chunk (extra details, a value phrased differently, several valid answers); the score could move by about 2.
low
correctness hinges on things the reference and chunk do not cover, or the reference itself looks wrong or ambiguous; the score could be off by 3 or more. Check these by hand first.

3Agent review

An open-book expert review by Claude (skill opalx-error-analysis): every fine-tuned answer checked against the reference and the OPALX manual, keep/drop per question, failure categories derived from the data, and benchmark ideas. The open in Error Analysis links load the review into the page like Import JSON (stored only in your browser, not sent to the sheet unless you change and send a question yourself).

4Recognition

100 multiple-choice questions (four options each) about chunks of the OPALX manual that are in the training data, asked in new wording. Nothing is generated: every option is scored by the summed log-probability of its tokens, and the most likely option is the model's answer, for the fine-tuned model and for its own base model on the same questions. Chance is 25 %. The main metric is raw cloze (plain text prompt, length-normalised score), which is fair to the base model. The other variants show the options in the prompt (letter) or use the training template (alpaca). Without guessable drops the questions a model without the manual (Sonnet, closed book) could answer, so distractor cues do not inflate the score. A large positive Δ means the knowledge is in the weights, not only reachable through one prompt format.

5Forgetting

Three standard benchmarks (1000 questions each, zero-shot, scored by log-likelihood like the recognition test): HellaSwag (commonsense sentence completion), WinoGrande (pronoun resolution), ARC-Challenge (grade-school science). Each adapter is compared with its own base model on the same questions. The forgetting score is the mean over the three tasks; Δ = fine-tuned − base in percentage points, so negative means forgetting. Intervals are 95 % (Wilson for accuracies, paired for Δ, paired bootstrap for the score). A Δ whose interval includes 0 is not distinguishable from no change.

6Training

Loss curves from Unsloth Studio (trainer_state.json of the newest checkpoint). The training loss is averaged into bins; the evaluation loss is Studio's own held-out set. The dotted vertical line marks the checkpoint that was evaluated on this page. Training loss far below evaluation loss, or an evaluation loss that turns upward, would indicate overfitting.

7Error Analysis

The Error Analysis pages are for human reviewers. Each shows one question at a time with its source chunk, the reference answer, the base model and the fine-tuned answer. Reviewers mark whether the example is worth keeping and whether the fine-tuned answer is correct, assign failure categories they define themselves, and press Send feedback; the feedback goes to a shared sheet. The LLM judge's score and certainty are under each answer (collapsed, open them after your own verdict), and the filter bar can restrict the page to a judge certainty or score range, e.g. to check the uncertain cases first.
